PostgreSQL CRUD for the-api

Generate REST routes from table names

the-api-routings provides Hono-compatible route metadata and automatic CRUD handlers for PostgreSQL tables in the the-api ecosystem. Configure a table once, then get consistent list, create, read, update, and delete behavior with filtering, joins, validation, permissions metadata, and soft delete support.

Before you start

Prerequisites

Node.js or Bun

Use Node.js 18+ or Bun 1+. This repository itself builds and tests with Bun.

the-api

Install the-api in the application that consumes this package.

PostgreSQL

CRUD SQL is PostgreSQL-oriented and uses JSON, trigram, ILIKE, and schema features.

Database setup

Example tables used in this documentation

These tables cover users, posts, categories, comments, soft delete, translations, joins, and search. Quoted identifiers preserve camelCase column names in PostgreSQL. 

CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  email TEXT,
  password TEXT NOT NULL,
  roles TEXT[] DEFAULT ARRAY[]::TEXT[],
  "userId" INTEGER,
  "isDeleted" BOOLEAN NOT NULL DEFAULT false,
  "timeCreated" TIMESTAMPTZ NOT NULL DEFAULT now(),
  "timeUpdated" TIMESTAMPTZ,
  "timeDeleted" TIMESTAMPTZ
);

CREATE TABLE categories (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL
);

CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  title TEXT NOT NULL,
  body TEXT,
  status TEXT DEFAULT 'draft',
  "categoryId" INTEGER REFERENCES categories(id),
  "userId" INTEGER REFERENCES users(id),
  "isDeleted" BOOLEAN NOT NULL DEFAULT false,
  "timeCreated" TIMESTAMPTZ NOT NULL DEFAULT now(),
  "timeUpdated" TIMESTAMPTZ,
  "timeDeleted" TIMESTAMPTZ
);

CREATE TABLE comments (
  id SERIAL PRIMARY KEY,
  "postId" INTEGER REFERENCES posts(id),
  "userId" INTEGER REFERENCES users(id),
  body TEXT NOT NULL,
  "isDeleted" BOOLEAN NOT NULL DEFAULT false,
  "timeCreated" TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE dict (
  id SERIAL PRIMARY KEY,
  lang TEXT NOT NULL,
  "textKey" TEXT NOT NULL,
  text TEXT NOT NULL
);

Quickstart

Register CRUD for a table

import { TheAPI } from 'the-api';
import { Routings } from 'the-api-routings';

const router = new Routings({
  migrationDirs: ['./migrations'],
});

router.crud({
  table: 'posts',
  searchFields: ['title', 'body'],
  defaultSort: '-timeCreated',
});

const api = new TheAPI({
  routings: [router],
});

await api.up();

curl 'http://localhost:7788/posts?_limit=10&_sort=-timeCreated'

Joins

Embed related data with PostgreSQL JSON

router.crud({
  table: 'posts',
  join: [
    {
      table: 'categories',
      alias: 'category',
      where: '"categories"."id" = "posts"."categoryId"',
      fields: ['id', 'name'],
      limit: 1,
      byIndex: 0,
      defaultValue: null,
    },
  ],
});
router.crud({
  table: 'posts',
  joinOnDemand: [
    {
      table: 'comments',
      alias: 'comments',
      where: '"comments"."postId" = "posts"."id"',
      fields: ['id', 'body', 'userId'],
      orderBy: '"timeCreated" DESC',
    },
  ],
});
curl 'http://localhost:7788/posts/1?_join=comments&_fields=id,title,comments'
router.crud({
  table: 'posts',
  join: [
    {
      table: 'comments',
      alias: 'commentsCount',
      field: 'COUNT(*)::int',
      where: '"comments"."postId" = "posts"."id"',
      defaultValue: 0,
    },
  ],
});

Joins are selected as COALESCE subqueries and may use json_build_object, jsonb_agg, custom scalar fields, leftJoin, whereBindings, ordering, and limits.

Normalized data

Return related records once with relations

Use relations for foreign-key data that clients need alongside a list. Rows keep their ids; the parent the-api application puts each related record in a top-level lookup map. This avoids repeating a category or user in every row. 

router.crud({
  table: 'posts',
  relations: {
    categoryId: {
      table: 'categories',
      fields: ['id', 'name'],
    },
    userId: {
      table: 'users',
      fields: ['id', 'name'],
    },
  },
});
curl 'http://localhost:7788/posts?_fields=id,title,categoryId,userId'
{
  "result": [
    { "id": 1, "title": "Hello API", "categoryId": 1, "userId": 1 },
    { "id": 2, "title": "Routing Guide", "categoryId": 2, "userId": 1 }
  ],
  "relations": {
    "categoryId": {
      "1": { "id": 1, "name": "News" },
      "2": { "id": 2, "name": "Guides" }
    },
    "userId": {
      "1": { "id": 1, "name": "Alice" }
    }
  }
}
for (const post of response.result) {
  const category = response.relations.categoryId?.[post.categoryId];
  const author = response.relations.userId?.[post.userId];
  renderPost(post, category?.name, author?.name);
}

Include the foreign-key field in _fields; relations are loaded from ids present in result. Use relationIdName when the target key is not id, for example { table: 'categories', relationIdName: 'slug', fields: ['slug', 'name'] } for a categorySlug field. A null or missing id has no relation entry. Keep sensitive fields out with the relation's fields or fieldRules.

Choose join when every row must embed nested SQL data. Choose relations for ordinary id references in a list: it deduplicates shared records. This package exposes relation metadata through c.var.relationsData; the parent the-api middleware creates the response map.

Fields

Hide, lock, and expose fields

router.crud({
  table: 'users',
  fieldRules: {
    hidden: ['password', 'email'],
    readOnly: ['id', 'timeCreated', 'timeUpdated', 'isDeleted'],
    visibleFor: {
      'users.view_email': ['email'],
    },
    editableFor: {
      'users.edit_status': ['status'],
    },
  },
});
BehaviorDetails
Hidden fieldsRemoved from results after query execution.
Read-only fieldsRemoved from POST/PATCH data.
Write whitelistWrite bodies are filtered to known table columns.
User ownership fieldIf present, userId is injected from c.var.user.userId.
Nullable numeric/date empty stringsNormalized to null.

Soft delete

Use isDeleted for reversible deletes

If a table has isDeleted, DELETE updates that field to true. GET requests automatically filter out deleted rows unless includeDeleted is enabled. 

router.crud({
  table: 'posts',
  includeDeleted: true,
  deletedReplacements: {
    title: '[deleted]',
    body: '',
    comments: 'NULL',
  },
});
curl -X DELETE 'http://localhost:7788/posts/3'
{
  "result": { "ok": true },
  "meta": { "countDeleted": 1 }
}

Permissions

Register route and field permission metadata

router.crud({
  table: 'posts',
  permissions: {
    methods: ['POST', 'PATCH', 'DELETE'],
  },
});

Permission names use <prefix-or-table>.<method>, for example posts.post, posts.patch, and posts.delete. The parent the-api application is responsible for enforcing route metadata. 

{
  "POST /posts": ["posts.post"],
  "PATCH /posts/:id": ["posts.patch"],
  "DELETE /posts/:id": ["posts.delete"]
}
router.crud({
  table: 'users',
  hiddenFields: ['email'],
  permissions: {
    owner: ['users.view_email'],
    fields: {
      viewable: {
        'users.view_email': ['email'],
      },
    },
  },
});

Validation

Generated and custom CRUD validation

crud() adds validation middleware generated from dbTables. It validates params, query parameters, headers, POST bodies, and PATCH bodies. 

router.crud({
  table: 'posts',
  validation: {
    body: {
      post: {
        title: { type: 'string', required: true },
        status: { type: 'enum', enum: ['draft', 'published'] },
      },
      patch: {
        status: { type: 'enum', enum: ['draft', 'published'] },
      },
    },
  },
});
RuleMeaning
typestring, number, boolean, date, enum, array, object, or an array of types.
requiredValue must be present and not empty.
enumAllowed values.
min, maxNumeric bounds.
preprocessTransform before validation.
items, propertiesNested array or object rules.

Set validation: {} to disable all generated validation, or validation: { body: {} } to disable body validation only.

Use PostgreSQL trigram and dict lookups

Search

router.crud({
  table: 'posts',
  searchFields: ['title', 'body'],
});
curl 'http://localhost:7788/posts?_search=routing'

Translations

router.crud({
  table: 'posts',
  translate: ['title'],
});
curl 'http://localhost:7788/posts?_lang=de&_fields=id,title'

When _search is used without _sort, results are ordered by generated _search_distance ascending.

Programmatic use

Use CrudBuilder inside custom handlers

import { CrudBuilder } from 'the-api-routings';

router.get('/my-posts', async (c) => {
  const crud = new CrudBuilder({
    table: 'posts',
    defaultSort: '-timeCreated',
  });

  const { result, meta } = await crud.getRequestResult(c, {
    _limit: ['10'],
    userId: [String(c.var.user?.userId)],
  });

  c.set('result', result);
  c.set('meta', meta);
});

Public operation methods are get(), getRequestResult(), getById(), add(), update(), and delete(). Self-documenting methods include optionsGet(), optionsAdd(), optionsUpdate(), and optionsDelete().

Security notes

Implemented protections and known gaps

Implemented

  • Sort fields are validated against known fields.
  • Untrusted query filter keys are validated.
  • POST/PATCH data is filtered to known table columns.
  • Read-only fields are removed from writes.
  • URL params are not merged into insert data.
  • Integer fields reject invalid numeric input.

Known gaps

  • Full owner-based route access control is not implemented.
  • keepUserId and needToCheckUserId are not ported.
  • _or, _isNull, and _whereNotIn query extraction are missing.
  • Hidden fields are removed after query execution.
  • Join-level permission is typed but not enforced.
  • fieldRules.editableFor is metadata only today.

    },
  },

{

Why do tests show 10 route entries for one CRUD resource?

There are five HTTP operations, but each generated operation has validation middleware plus the final handler. The current pushToRoutes() implementation stores each created handler entry separately, so tests see 10 route records.
